# Triage and Edge Cases

本文件只用于 `EXCEPTION` 慢通道的快速路由；默认先走命名快通道，不把全库预先分成三档。

## 命名快通道

1. **`NAMING_PASS`**：现名已符合命名合同；无动作，命名复扫后立即退出深查，只进最终对账。
2. **`NAMING_READY`**：身份、导演、年份、归属和 sidecar 事实可从现有名称/结构唯一保留，只做合同规定的语法规范化；生成完整 naming bundle（现有 NFO 逐字 old/new，缺失则显式记录且不补造）后进入 10–20 项计划。
3. **`EXCEPTION`**：语义事实、特殊结构、sidecar 配对、Unicode/实体、版本关系或目标碰撞存在不确定性；不得在快通道猜名、覆盖或加后缀。

快通道禁止读 NFO 内容、运行 `ffprobe`/IMDb、计算完整 hash、去重或深度归类；这些工具只按需用于本文件所述慢通道。

## EXCEPTION 慢通道分流

1. **明确**：`TASK_ROOT` 内，身份与 sidecar 已闭环，目标可唯一复算；查证后回到 naming bundle/计划门禁。
2. **待查**：可通过最小 NFO、`ffprobe` 或 IMDb suggestion 核验；不闭环前不得执行，也不得直接扩大为整夹待确认。
3. **冲突**：多候选、归属歧义、版本差异、不可逆路径风险、目标碰撞或边界故障；原地记录并按 `failure-handling.md` 处理。

三档只对 `EXCEPTION` 使用，且不阻塞已经通过快通道的批次。

## 重复、版本与差异

- 精确重复只认完整文件 hash（内容+清单一致）；完整 hash 仅在目标碰撞形成的候选重复或异常完整性场景生成。
- 抽样 hash、时长、分辨率仅作辅助；任意差异默认保留多版本，不删、不覆盖，进入冲突/待确认路径。
- 误判风险条目保持原地，先记录证据并按 B08 处理。

## 主视频与 sidecar

- 主视频与 NFO/字幕/sidecar 采用同级、同 stem、同电影夹事实闭环；快通道只在现有事实可保留时配对，不凭扩展名或最长文件猜主视频。
- 合同已明确判为垃圾的无语言标识字幕（如 `video.srt`）直接归类为垃圾，计划内预锁 `trash_target` 后可逆移入 `TASK_ROOT/_trash_<task-id>_<YYYYMMDD>/`；不得猜语言或转入待查/待确认。
- 只有合同未定性且 sidecar 身份/配对仍不确定时，才单独隔离 sidecar，避免“整夹待确认”；`TASK_ROOT/_待确认_` 严格按最小结构存放。

## 字符与结构异常

- 空格、单引号、重音、特殊字符问题先按实体可达性/逐字路径验证，不做 NFC/NFD 猜名。
- `Errno39`、双实体、跨卷不可达直接映射到 B05；多视频、DVD/蓝光结构、合集或父目录目标碰撞进入 EXCEPTION。

## 括号式→点式转换（v1.3）

大量电影夹使用 `中文名 英文名 (年份)` 格式（括号式），需转为合同格式 `中文名.英文 Name.年份`（点式）。

**转换条件（全部满足才可自动执行）：**
1. 同目录下存在视频文件（mkv/mp4/avi/iso）。
2. 可从视频文件名提取英文名（正则 `^([A-Za-z].+?)\.(\d{4})\.` 或 `^([A-Za-z].+?)\s+(\d{4})\s`）。
3. 提取的英文名非空且长度 ≥ 2。
4. 新路径不存在同级碰撞。

**转换步骤：**
1. 提取英文名，将其中的 `.` 替换为空格（年份及之后保持点分隔）。
2. 生成新名：`中文名.英文名.年份`。
3. `os.rename(旧路径, 新路径)`，验证新路径存在且旧路径消失。
4. 无法提取英文名的标为 `EXCEPTION`，不猜名。

## 中文视频文件名清理（v1.3）

视频文件名中不应有中文（合同规定"文件名里不要中文"）。

**清理条件：**
1. 文件扩展名为视频类型（mkv/mp4/avi/iso）。
2. 文件名以中文字符开头（`\u4e00-\u9fff`）。

**清理步骤：**
1. 正则分离：`^([\u4e00-\u9fff\u3000-\u303f\uff00-\uffef、·]+)[\s.](.+)$`
2. 保留第2组（英文/原文部分），将其中的 `.` 替换为空格（年份后保持点分隔）。
3. 若分离失败或结果为空，标为 `EXCEPTION`。

## CIFS 大小写双目录伪影（v1.3）

在 CIFS/SMB 挂载的 NAS 上，仅大小写不同的目录名可能同时存在（不同 inode，内容相同）。

**检测方式：**
1. 目标路径已存在时，检查源路径和目标路径的 inode 是否不同。
2. 若 inode 不同且文件列表完全一致（名称+大小），判定为 CIFS 伪影。

**处理方式：**
- 跳过该重命名，标记为冲突。
- 不强制合并，不删除任一版本。
- 在工作单中记录双目录路径和 inode。

## 特殊容器归位（v1.3）

`DVD/`、`蓝光/`、`短片/`、`纪录片/`、`访谈花絮/`、`长片/`、`BFI Complete Shorts/` 等是非标准结构容器。

**处理流程：**
1. 有视频文件的：为每部电影创建独立 film folder（从视频文件名提取英文名），移入。
2. 空目录：递归删除（从深到浅）。
3. 有子目录的：逐个检查，按括号式/点式规则处理。
4. 访谈花絮中的其他导演作品：标为 `EXCEPTION`，不移入当前导演夹。

## 年份冲突三源验证（v1.3）

目录年份与视频 release 年份不一致时，用 IMDb suggestion API 验证。

**验证方式：**
1. `curl -s "https://v2.sg.media-imdb.com/suggestion/x/<关键词>.json"`
2. 取第一条结果的 `y` 字段作为确认年份。

**修正规则：**
- 目录年份改为确认年份。
- 视频文件保留 release 原始年份 token（合同规则）。
- 无法确认的标为 `EXCEPTION` 冻结。

## 跨任务根与回收旁路

- 跨任务根移动/跨国合并一律判冲突，不得直接转移；合集先在 `TASK_ROOT` 内拆分为可闭环小单元。
- `.DS_Store`、`._*` 可按命名合同直接删除；其余垃圾优先可逆 `mv` 到固定 `TASK_ROOT/_trash_<task-id>_<YYYYMMDD>/`，并预锁目标。
- 无法确认归属项不得跨任务根回收或重排；未覆盖场景按 `failure-handling.md` 的 `Bxx` 继续。
