# Lessons and Audit Checklist

仅在设计审计、复盘事故或出现疑似回归时读取。历史案例只提供背景，不改变现行合同。

## 防回归检查表

1. 扫描产物是否保存了逐字路径、inode、size 和 Unicode 形态？
2. 标准卡是否列出所有高频模式和明确/待查/冲突数量？
3. 明确项是否被不必要的网络查证拖慢？
4. 待查项是否超过三次尝试仍留在执行队列？
5. 冲突项是否被并入批量计划？
6. 锁定计划哈希是否在执行前记录？
7. 文件/sidecar 是否先处理，目录是否最后改名？
8. 每个 move 是否核对 old exists/new absent/target exists？
9. 回收站是否保层级、列大小并可逆？
10. 每批是否复扫旧路径残留和非白名单残留？

## 历史教训索引

- 先提级再删空壳，顺序反了会导致 Directory not empty。
- 目录名最后改，否则后续路径失效；脚本变量保存旧路径。
- SMB `._*` 可能在清理时已消失，ENOENT 单独记录，不中断批次。
- 空格与点是不同 token；手打路径容易把 `Weekend Lover` 写成 `Weekend.Lover`。
- 网络 ffprobe 慢，批量走容器通道；单文件可接受。
- UUID 可能是普通文件，先确认类型。
- `os.walk` 会超时，按国/导演分块。
- mv 目标必须是最终规范名；备注字符会变成真实目录。
- 移动后立即 listdir 验证扁平性和位置。
- `movie.nfo` 只认所在夹内视频。
- 计划 JSON 先人工复核 sample、广告、错配 NFO 和字幕 basename。

## 2026-08-25 韩国库批次新增教训

- **⚠️ 最高优先级：电影夹名 = 中文名 + "." + 主视频文件完整 stem（逐字保留整个 release 尾巴）**。绝不允许自造 `中文.English.年份` 短格式砍掉尺寸/编码/发布组——jellyfin 靠这些 token 匹配版本；正确样例：`单身男女.Don't Go Breaking My Heart.2011.BluRay.720p.DTS.2Audio.x264-CHD`。
- 文件名标准形态：**标题段点转空格、年份及之后保持点分隔**（`Don't Go Breaking My Heart.2011.BluRay.720p.DTS.2Audio.x264-CHD.mkv`），不是全空格也不是全点。
- 从文件名重建夹名时禁止用"最长文件名当主视频"启发式——残缺名（`of Murder.2003...8G]`）会污染夹名并反向生成坏文件名；主视频应结合 NFO/大小/命名质量挑选。
- 过滤中文段重建 stem 时必须兜底：若结果为空（如纯中文名文件），保留原 stem，绝不产出 `.mp4` 这类空 stem。
- 目录年用查证年的规则在"从文件重建"流程里会被冲掉（release 原 token 回流到目录位），重建后需重放年份修正表。
- 广告/网址模式会误伤 YYeTs 类发布组（文件名含"韩语中字"等中文组名）：广告判定只看纯广告内容（`^\d+[.、]` 前缀、sample、高清控联盟），YYeTs 正片先查证再动，误伤立即从回收站恢复并记录。
- 清理"空壳"前必须重新实时 listdir：拍平/移动后浮出的新空壳（如 TLF 压制版）用旧路径清理会扑空；"清单夹"可能是导演私人片单收藏（内含他人经典），须用户裁决后才删。
- 同片异译名重复（《神偷猎人断指客》=《好家伙坏家伙怪家伙》）：按译名对照表核查后再判重；多版本按用户裁决"时长相同留画质好"，DVD 版让位 BluRay 版。
- 目录改名映射 JSON 里 old 必须含完整相对路径（导演/夹），执行端不得再拼导演前缀，否则路径翻倍全批 FAIL（幂等重跑可自愈）。
- 中英混合夹名生成目标名时防重复拼接：`呼吸 Breath.2007` + 英文段 → 不能产出 `呼吸 Breath.2007.Breath.2007`；生成后跑正则终检兜底。
- 纯英文电影夹（No Other Choice.2025）补中文名缺证据时保留原名，不强造。
- jellyfin 容器无独立 ffmpeg PATH 且媒体盘未挂进容器；MKV 时长可自写 EBML Duration 解析器读头部 512KB 获取（TimestampScale 默认 1ms）。
- Wikipedia REST summary 对通用词（Time/Grass/Sunny）限流且消歧页多，同年命中才算过；搜索接口 action=query&list=search 可作第二确认源。
- 华语导演英文名需任一可信源确认，拼错破坏刮削。
- FUSE 幻影可能让 rename 看似成功；stat 新路径和数据所在实体是必要验证。
- 脚本报错先核对现场，不盲目重跑；check-and-rename 幂等兜底。
- 多 CD 文件保留 part/cd 后缀，sidecar 同步对齐。
- 批处理脚本的回收站目标必须包含源文件的完整相对路径或唯一序号；仅用 `movie.nfo`、`RARBG.txt` 等 basename 会导致后续项目冲突并留在原夹。
- 干跑不能假设后续 rename/move 已发生：要么维护虚拟路径状态，要么在 dry-run 使用原路径、执行模式使用新路径；执行后必须以实时树复扫，不能把 dry-run 的 MISSING 当成现场事实。
- 散落视频收拢时必须先创建电影夹，再把视频放入夹内；禁止把“电影夹名”直接当成无扩展名文件目标。视频 basename 仍须纯英文，中文只留在电影夹名。
- sidecar 语言后缀可为复合标识（如 `.chs.eng`、`.cht.eng`）；审计器不能把合法复合语言字幕误报为错配。
- 任何误分类文件进回收站后，批次验收必须按唯一回收站路径核对并能恢复；不要依赖原 basename 搜索。
- **无语言标识的字幕也不是合法同名 sidecar**：`video.srt` 不能默认当作字幕配对；若无法从证据确认 `.chs/.cht/.eng` 等语言标识，移入回收站并报告，不猜语言。
- .33 的媒体共享写入通常需要 `sudo -n python3`；普通用户 dry-run 可读，正式 `rename/mv/unlink` 先核对权限后使用 sudo，不要改宽共享权限。
- **sudo 执行阶段只读锁定计划**：普通用户生成的 `/tmp` 计划文件可能无法被受限 sudo Python 重写；dry-run 负责写计划，`--exec` 只读取并校验哈希后执行，避免权限错误或计划漂移。
- **计划执行器必须过滤同路径 no-op**：当源电影夹名已经等于最终 release stem、仅需改父导演夹时，不得生成 `old == new` 的自移动；若批次中断，恢复器须同时检查锁定动作的临时路径与 `final` 路径，跳过已完成动作后再继续，不能盲目重跑。
- **115/CD2 目录名 Unicode 形态逐夹核对**：同一库内 NFC 与 NFD 混存（如 `István Szabó` NFD、`Áron Gauder` NFC）；路径常量必须按现场 repr 逐一确认形态，不能假设全库一致；源路径找不到时先试另一形态再报 MISSING。
- **FUSE 空目录会自收缩**：子文件提级后 `Subs/` 等空壳可能直接消失（mv 报 MISSING 属正常）；执行后以实时 listdir 为准。反向坑：`rename(空壳→有内容的同名目标)` 会报 Errno 39 Directory not empty，即使 listdir 显示目标"为空"也可能含幻影条目——此时把空壳 mv 进回收站留证即可。
- **同片多版本但时长未证实的（如《撒旦探戈》265 内置字 vs usury 外挂、《诅咒》WEB-DL vs D9、《雁南飞》CC-146 vs FGT）一律按冲突保留双版**，不得凭分辨率猜删；《诅咒》两版时长不同属不同剪辑更是必须并存。
- **115 空目录删除要重试**：mv 走子目录后父壳 rename 可能连续报 Errno 39，但间隔一次操作后再试即可成功；空壳清场脚本应"先移子、再移根、失败留待下轮"，不要当死锁放弃。
- **"归国归导"批次先移整夹不改名**：跨国归位时只把源文件夹整体 mv 到目标导演夹下（导演夹不存在才新建），文件级命名/sidecar 规范化留给对应国家批次统一做；这样计划最小、可逆性最好，也避免在错误国家上下文里做精细改名。
- **NFD 目录名不能写字面量常量**：如 `François` 的 NFD 形态在脚本字符串里会静默失配（resolve 报 MISSING 但目录明明在）。凡含重音字符的路径必须 `os.scandir` 现场扫描后取 `d.path`，或先打印 repr 核对形态；`endswith('Ozon')` 这类 ASCII 尾缀匹配最稳。
- **计划哈希必须确定性**：Python `hash()` 每次进程随机化，绝不可用于生成回收站后缀或计划内容；用 `enumerate` 序号、relpath 或 sha1。
- **同名原则的严格边界**：只有"夹名相同且内容为精确重复（抽样 SHA 一致）"才可自动合并删除；同名但不同压制/剪辑的多版本必须并列保留待 ffprobe 裁决；压缩包是某版本唯一载体时即使无视频也不得清。
- **多版本裁决流水线**：ffprobe 双版时长→差 <1min 视为同剪辑（留大码率/高分辨率，另一版整夹回收）；差 >1min 视为不同剪辑必须并存。并存版命名需用户批准后缀（如 `片名 (年) 意语配音版`），批准后移入本体导演夹、原 NFD 壳清空回收。
- **执行器必须容忍 n=None 的 delete 项**：Apple 垃圾 delete 操作无 new 字段，恢复/续跑时取 `n or fin` 会得 None 导致 dirname(None) 崩溃；delete 分支必须先于 tgt 计算处理。
- **CC 版电影夹名带 @CC 标记的（如 `扒手 Pickpocket @CC`）**：@CC 是来源备注不是片名成分，规范化时去掉；夹内 CC 官方 Extras 子目录保留为 `Extras/`。
- **重音字符匹配用"去变音符比对"**：`Américaine` 的 NFD 形态与字面 NFC 常量永远不相等；匹配时先 `NFD 分解→去 combining 字符` 再比较（如 `Americaine==Americaine`），比逐形态尝试更稳。目标命名同理：新文件名直接采用去重音形式可避免后续所有形态问题。
- **同 release 重复夹识别先比文件清单**：两个夹内 mkv/srt/nfo/md5 完全同名同 stem 即同一发布；ffprobe 时长一致后整夹回收，保留带海报等完整元数据的版本。
